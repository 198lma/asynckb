# 性能与短时压力测试

## 范围

使用当前 asynckb 源码连接 KES MySQL、Oracle、SQL Server 三模式，按模式顺序执行。
这是独立的非功能测试，7 个场景、三模式共 21 组，不计入七模块功能测试点或 pytest 节点数。
2026-11-19 精简后的功能基线为 160 个测试点、669 个参数化节点。

| 脚本场景名 | 测试内容 | 负载与核对方式 |
| --- | --- | --- |
| `single_cache_0` | 单连接，无语句缓存 | 连续参数查询；核对返回值 |
| `single_cache_100` | 单连接，启用语句缓存 | 相同查询及参数类型；核对返回值 |
| `pool_workers_1` | 连接池低并发 | 8 个池连接，1 个任务 |
| `pool_workers_8` | 连接池等量并发 | 8 个池连接，8 个任务 |
| `pool_workers_32` | 连接池排队并发 | 8 个池连接，32 个任务 |
| `sustained_workers_32` | 持续查询压力 | 8 个池连接，32 个任务，默认持续 120 秒 |
| `transaction_mix` | 并发事务读写 | 32 个任务，插入并核对整数、256 字符文本及 Decimal；交替提交/回滚 |

查询路径先执行 100 次预热，预热不计入计时。事务场景的表为每轮随机创建的
`kb_perf_<随机后缀>`，不访问业务表；结束时按已完成提交数核对实际行数，再删除测试表。
事务吞吐的单位为“事务/秒”，不能与查询吞吐直接比较。

另检查：池满时获取连接发生预期超时；释放后可再次查询；所有连接归还；
关闭池后仅留下观察连接；删除测试表并关闭观察连接。

## 指标与判定

- 记录成功操作数、操作/秒、端到端 P50/P95/P99/最大延迟、错误数及类型。
- 连接池延迟包含等待、获取连接、查询及连接归还/重置；单连接不包含建连初始化。
- 记录客户端 CPU 时间，每秒采样客户端 RSS、文件描述符及 asyncio 任务数量。
- 查询按返回值核对；事务按行内容和最终提交行数核对。错误数必须为 0。
- 不设置未经约定的吞吐/延迟验收阈值；性能指标作为当前环境基线，不据此认定达到生产容量要求。
- RSS 包含 Python 内存分配器和测试采样数组；短时 RSS 上升不能直接认定为驱动内存泄漏。
- 这是本地闭环负载，客户端与数据库共享资源、关闭 TLS；未覆盖长时间长稳、真实网络及生产容量。
- 未与原版 asyncpg 做同环境对照，不能据此宣称相对原版的性能提升或下降。

## 执行

在仓库根目录设置与功能测试相同的 `ASYNCKB_KES_*` 环境变量，数据库默认为 `test`。
密码不写入证据文件。

```bash
export ASYNCKB_KES_PASSWORD='<测试密码>'
python3 -m unittest discover -s tools/tests -p test_kes_performance.py -v
python3 -W error::ResourceWarning -W error::RuntimeWarning \
  tools/run_kes_performance.py \
  --seconds 10 --stress-seconds 120 \
  --output docs/_static/kes-testing/performance/results-20261119.json
```

三模式各执行 7 个负载场景，每种模式计时约 180 秒，总计约 9 分钟，加上建连与清理时间。
命令最多允许常规场景 60 秒、持续场景 600 秒；固定最多 8 个池连接、32 个并发任务。
脚本非零退出或结果中的 `passed=false` 均不能计为通过。

实测结果见 [性能与压力测试结果](PERFORMANCE_RESULTS.md)，原始数据包含逐秒资源采样。
