密码算法在现有本机实例上使用唯一临时角色、仅针对这些角色的 HBA 规则验证。

## 各方式结论

下列结果均覆盖三模式。

| 方式 | 实际结果与边界 |
| --- | --- |
| SCRAM-SHA-256 | 成功；验证 SASL 握手、正误/缺失/空密码及伪造签名、nonce、未知机制拒绝 |
| Cleartext Password | 成功；分别验证 MD5/SCRAM 存储的用户密码；生产应使用 TLS，不能把明文机制当作传输加密 |
| MD5 | 成功；MD5 存储走请求 5；HBA 配置 md5 但存储为 SCRAM 时实际走 SCRAM，分别核对而非混记 |
| trust | 成功；故意错误密码仍可连接，确认无密码挑战；不视为密码校验成功 |
| cert | 成功；可信 CA、正确客户端 CN 可连接；错误 CN、缺少客户端证书均拒绝 |
| peer | 成功；通过实际 KES Unix socket 验证操作系统身份；同用户成功、不同用户拒绝 |
| LDAP | 成功；真实 LDAP Bind 服务收到正确/错误凭证，并分别允许/拒绝 |
| RADIUS | 成功；真实 UDP RADIUS 请求，正确/错误凭证分别得到 Access-Accept/Reject |
| ident | 成功；隔离网络真实 113 端口服务返回匹配/不匹配身份，分别允许/拒绝 |
| PAM | **未完成登录验证**；已构造进程私有 PAM 服务与密码库，但三套 KES 均报 `"pam": not supported by this build`；6 项正误密码登录跳过，另 3 项记录服务端配置限制 |
| BSD | **未完成 BSD 系统认证验证**；当前 Linux 三套 KES 均不接受 bsd 认证配置，3 项通过仅表示限制被确认，不表示登录成功 |

LDAP/RADIUS 密码故意不同于数据库角色密码，且断言外部服务实际收到的身份及
凭证判定结果，避免因数据库密码或宽泛 trust 规则导致假阳性。
该测试验证协议互通，不覆盖企业目录结构、远程服务高可用或生产 CA 运维。

## MAC 上传验证

服务端按需发送编号 `19` 的 MAC 请求，驱动根据已连接 TCP socket 的本地地址
定位 Linux 网卡，返回该接口的实际 MAC；不使用随机或任意网卡的 node ID。
实际出站网卡值与内核 sysfs 独立核对，IPv4/IPv6 回环均返回全零地址。

| 场景 | 三模式实测 |
| --- | --- |
| HBA 配置匹配的回环 MAC | 登录和查询成功；握手 `[19, 10, 11, 12, 0]` |
| HBA 配置错误 MAC，紧接 reject 兜底 | 拒绝；只收到 `[19]`，无认证成功 |
| sso 调用 `src_restrict.add_rules(0, user, ip, NULL, 'mac=...')` 配置匹配白名单 | 登录和查询成功；握手 `[19, 10, 11, 12, 0]` |
| 上述白名单的 MAC 不匹配 | 拒绝；握手 `[19]` |
| 上述白名单 MAC 正确但密码错误 | 密码认证拒绝；握手 `[19, 10, 11]`，不能绕过密码校验 |

以上报文中的实际上传值为 `00:00:00:00:00:00`，对应真实回环接口。
白名单专用临时实例加载 `src_restrict`；移除可能掩盖结果的宽泛 TCP allow 规则，
再调用新增规则接口，并显式等待重载。sso 是临时实例内置的安全管理员，通过该
临时实例的本地 trust socket 使用；未创建或修改现有业务实例的 sso 密码。

本轮选择用户给出的第一种验法（白名单 + limited_info）。
**未验证第二种验法中的服务端登录记录 MAC 展示/审计落库**，不能用代理捕获到
MAC 报文替代审计结果。MAC 由客户端上报，不是防伪身份凭证。
当前接口发现实现只支持 Linux，其他平台明确报错；不能声称已完成 Windows/macOS
客户端上传适配。测试不证明任意网卡别名、复杂路由或远程网络拓扑均已验证。

## 源码修复

1. 协议层增加请求编号 19 的响应，返回 null 结尾的实际接口 MAC。
2. KES 完整 Unix socket 路径 `.s.KINGBASE.<port>` 不再被错误拼接 PG socket 名，恢复 peer 连接。
3. 使用结构化分隔/转义解析修正密码文件中的冒号、反斜杠处理；忽略不完整记录，避免解包异常。
4. Cleartext 请求遇到缺失密码时发送空值，由服务端明确拒绝，不再因 `None.encode()` 变成客户端内部异常。

本次未新增认证选择参数。SCRAM/MD5/Cleartext、TLS 及外部认证主体流程沿用原实现。
测试根据诊断结果修正了隔离环境的 Oracle 必需 `plsql` 预加载及测试用户 SCRAM
密码存储设置，不把这些环境问题归类为驱动算法缺陷。
